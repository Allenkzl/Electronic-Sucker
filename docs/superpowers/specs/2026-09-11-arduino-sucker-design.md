# 电子吸盘浏览器控制器 — 设计文档

日期：2026-09-11
状态：已实现并实测通过

## 1. 目标

在浏览器网页上点「吸取 / 放下」两个按钮，通过 Arduino Uno 控制电子吸盘与电磁阀，
实现取放料动作。要求断电或程序异常时不能把气泵一直开着烧掉。

## 2. 硬件与原理

### 接线

| Arduino Uno | 接到 | 信号含义 |
|---|---|---|
| A0（数字 14） | 吸盘 / 气泵 模块信号线 | `180` = 吸，`0` = 停 |
| A2（数字 16） | 电磁阀 模块信号线 | `180` = 进气放料，`0` = 关 |
| GND | 外部电源负极 | 必须共地 |

气泵与电磁阀由**外部电源独立供电**（确认过），不经 Arduino 的 5V。

### 关键判断：控制信号是舵机式 PWM

厂家参考代码用的是 `Servo` 库，而不是 `digitalWrite`。据此判定模块的控制输入是
**舵机式 PWM 信号**（`write(180)` 开、`write(0)` 关），不是简单的高低电平。
固件因此沿用同一套信号，保持与厂家模块的兼容性。

Uno 的 A0/A2 同时就是数字引脚 14/16，Servo 库可以正常驱动，因此**硬件接线无需改动**，
只把厂家代码里的引脚 8/9 改为 A0/A2（并按用户实际接线把阀与泵的角色对调）。

考虑到存在「模块其实是两线通断型」的可能，固件保留 `MODE digital`，
可切换到普通高低电平输出，无需改线或改硬件。

## 3. 架构与选型

```
浏览器网页 ──HTTP/SSE──> Python 桥接服务 ──串口 115200──> Arduino 固件 ──PWM──> 吸盘/电磁阀
```

### 为什么用 Python 桥接，而不是浏览器 Web Serial 直连

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Python 桥接（选用）** | pyserial 已装、零新增依赖；Chrome/Safari 都能用；安全兜底可放在服务端（断线自动关、退出即 STOP）；可做自动重连与心跳 | 多一个进程 | **选用** |
| Web Serial API | 无需后端 | 仅 Chrome/Edge；兜底逻辑只能在前端，页面一崩就失控 | 备选 |

服务只绑定 `127.0.0.1:8787`，不占用 DSH GUI 的 3080 端口，局域网内其他设备无法访问。

## 4. 固件设计（`firmware/sucker/sucker.ino`）

常驻命令驱动（区别于厂家示例把动作写死在 `setup()` 里只跑一次）。

### 串口协议

115200 8N1，`\n` 结尾，不区分大小写。

| 命令 | 作用 |
|---|---|
| `PICK [ms]` | 吸盘开；`ms > 0` 到点自关，缺省用 `pick_ms` |
| `DROP [ms]` | 吸盘关 + 电磁阀脉冲进气放料 |
| `STOP` | 两路全关 |
| `SET pick_ms\|drop_ms\|watchdog N` | 参数设置 |
| `MODE servo\|digital` | 输出模式 |
| `STATUS` / `PING` | 状态 JSON / 心跳 |

状态变化主动上报 `{"ev":"state",...}`，前端据此实时刷新。

### 动作语义

- **吸取**：先关电磁阀（否则真空被破坏）→ 开气泵 → `pick_ms = 0` 时一直保持。
- **放下**：先关气泵 → 开电磁阀脉冲 `drop_ms`（默认 800ms，同厂家代码）→ 自动关闭。

### 安全机制

1. **上电即关闭**：`setup()` 里先把两个输出脚拉低再交给 Servo 库，不会一插电就吸住。
2. **看门狗**：超过 `watchdog` 毫秒没有收到任何命令且处于开启态，自动全关。
   这是防止上位机崩溃/USB 掉线后气泵空转烧毁的最后防线。
3. **退出即断电**：桥接服务收到 SIGINT/SIGTERM 时先发 `STOP`。

## 5. 桥接服务设计（`bridge/bridge.py`）

- 标准库 `ThreadingHTTPServer` + pyserial，无第三方 Web 框架。
- 自动探测串口（优先 `wchusbserial` / `usbmodem`），失败后每 2 秒重连。
- 后台串口线程负责收发与状态机；HTTP 线程通过锁串行化写操作。
- 事件通过 SSE（`/api/events`）推送，避免引入 WebSocket 依赖。

| 接口 | 作用 |
|---|---|
| `GET /` | 控制网页 |
| `GET /api/status` | 串口 + 设备实时状态 |
| `GET /api/events` | SSE 实时推送 |
| `POST /api/pick` `{pick_ms}` | 吸取 |
| `POST /api/drop` `{drop_ms}` | 放下 |
| `POST /api/stop` | 急停 |
| `POST /api/settings` | 参数下发并持久化到 `bridge/settings.json` |

## 6. 前端设计（`web/index.html`）

单文件、无构建步骤。暗色控制台风格，两个大按钮 + 急停条 + 双状态灯 + 参数面板 + 运行日志。
响应式（手机可用）、支持键盘快捷键（空格 / 回车 / Esc）、`prefers-reduced-motion` 降级。

## 7. 实测中发现并修复的真实缺陷

两个缺陷都是**只在反复真实操作下才会暴露**的，静态阅读代码不容易发现。

### 7.1 固件看门狗无符号下溢（严重）

**症状**：点「吸取」后偶尔立刻自己松开；连续操作时随机复现。

**根因**：`loop()` 在**开头**取 `unsigned long now = millis()`，
而串口命令是在那之后处理的，`handleLine()` 把 `lastCmdAt` 写成了比 `now` 更晚的时间。
于是 `now - lastCmdAt` 在无符号运算下下溢为约 43 亿，`> watchdogMs` 恒成立，
看门狗在刚收到命令的瞬间就被误触发。

**修复**：
1. 把 `now` 的取值移到串口处理**之后**，保证 `lastCmdAt <= now`；
2. 看门狗比较改用有符号 `(long)(now - lastCmdAt) > (long)watchdogMs` 再兜一层底。

**回归测试**：`python3 tools/serial_test.py --stress 40`
连续 PICK/DROP 40 轮，精确匹配 `"ev":"watchdog"` 统计误触发，必须为 0。

### 7.2 看门狗超时与心跳间隔余量不足

**症状**：桥接服务正常运行时看门狗仍然触发。

**根因**：测试过程中把 `watchdog` 设为 4000 ms 并持久化，而心跳间隔是 3000 ms，
只剩 1 秒余量，稍有调度抖动就误判为失联。

**修复**：心跳间隔降到 1.5 s；看门狗设 **6000 ms 安全下限**，
设置更小的值会被自动抬高并在日志里给出提示。

### 7.3 前端 `e.target.matches is not a function`

快捷键处理里直接调用 `e.target.matches(...)`，当事件目标是 `document` 本身时抛异常。
已加类型保护。

## 9. 已知限制

- 页面关闭但服务仍在运行时，吸盘保持当前状态（有意设计，避免误关网页掉件）；
  要立即松开请点「急停」。
- 打开串口时原厂 Uno 会因 DTR 复位一次；本机的 CH340 兼容板实测**不复位**，
  因此握手同时接受开机 `READY` 和 `PING` 回显 `PONG` 两种信号。
- 若模块方向与预期相反，把固件里 `ANGLE_ON` / `ANGLE_OFF` 对调即可。
